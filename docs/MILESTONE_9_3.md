# Milestone 9.3: source-driven water, HDR adaptation and renderer validation

## Result

M9.3 replaces the last fixed M9.2 exposure shortcut with render work derived
from the original `WaterPlane`, `HDREffect`, `BloomEffect`,
`ToneMappingEffect`, `IActor::Lighting` and `FxEmitter` implementations.
It also makes those paths observable: a race-render smoke now fails when a
required pass was not begun or submitted.

No Parallels/Windows run is part of this milestone.

## WaterPlane and reflection

World2 water now uses the three resources bound by the Windows
`GraphManager::InitWaterPlane` path:

- the rendered scene depth attachment;
- `Data/Misc/water00.png` as the two scrolling normal samples;
- the planar-reflection render target.

The scene is rendered to a separate full-resolution RGBA16F color/depth
target before the Water pass. The pass copies the source color to the HDR
target and then evaluates the source water colour `(0, 0.2, 0.5)`, normal
scroll rate `dt * 0.15`, cloud intensity `0.1`, Fresnel reflection,
specular highlight, fog and depth-dependent alpha. This avoids sampling a
depth attachment while it is bound for output. Low-quality
`waterColor.dds` remains available to the non-water surface path.

The Reflection pass remains conditional. It is mandatory for World2 water
and World5 `glPlanarRefl` environments and is omitted for worlds that do not
request it.

## Original HDR chain

The portable render graph now mirrors `HDREffect.cpp`:

1. logarithmic 3×3 luminance reduction to 64×64;
2. 4×4 reductions to 16×16 and 4×4;
3. a final exponential reduction to 1×1;
4. ping-pong temporal adaptation with
   `old + (current - old) * (1 - 0.98^(30 * dt/2))`;
5. 128×128 bright-pass and separable bloom;
6. the `toneMapping.fx` exposure, adapted average/peak luminance and bloom
   composite.

Adaptation is reset when render targets are recreated. The current and
previous 1×1 textures stay on the GPU; no synchronous read-back or
frame-stalling CPU copy is introduced.

## Material and Fx mapping

`db.xml/grActor/graphLighting` is no longer reduced to one boolean. The
loader preserves `glNone`, `glStd`, `glPix`, `glRefl`, `glBump`, `glRefr`
and `glPlanarRefl`, including the source lighting mode for vehicle bodies.
The portable material shader dispatches unlit, per-pixel, reflective,
bump-detail, refractive and planar-reflection branches from that value.

`FxEmitter` loading now additionally preserves:

- `maxNumAction`;
- `startRot`;
- `rangeLife`, `rangePos`, `rangeScale` and `rangeRot`;
- `speedRot`;
- point-sprite, sprite, directional-sprite, plane, trail and node manager
  selection.

The renderer applies the ranges deterministically per source particle,
updates particle orientation, uses local planes for plane/node managers,
and uses the source velocity basis for directional/trail submissions.
The trail branch is a directed portable segment, not yet the legacy
dynamic connected strip generated by `FxTrailManager::DrawPath`.

## Renderer telemetry

`GraphicsDevice` exposes backend-neutral per-frame pass telemetry. The
bgfx/Metal backend counts pass begins and successful draw submissions for:

- Reflection, Shadow, Scene and Water;
- Luminance64, Luminance16, Luminance4, Luminance1 and LuminanceAdapt;
- BloomExtract, BloomHorizontal, BloomVertical and Composite;
- Overlay.

`--race-render-smoke-test` validates the common graph on every map and adds
conditional Reflection/Water requirements from the selected original
environment. A touched-but-empty required rendering pass does not pass the
check. The same run switches between both original camera modes, verifies
that all six racers reached the renderer, and recreates every frame target
at a second size and back before entering the race.

The wider map matrix also exposed two non-renderer portability defects that
the World1-only M9.2 smoke could not see:

- the original World2 directory is named lowercase `texture`; both weather
  call sites now use its exact case on APFS;
- some configured opponent motors have `maxRPM <= 4000`, which violated
  Jolt's fixed 4000 RPM automatic-shift default. Jolt shift-up/down points
  are now scaled to each original `db.xml` motor.

## Verification matrix

The source-data audit covers representative renderer feature groups:

```bash
build/macos-arm64-m9/Debug/RRR3d --verify-resources --track=0
build/macos-arm64-m9/Debug/RRR3d --verify-resources --track=16 --weather=rainy
build/macos-arm64-m9/Debug/RRR3d --verify-resources --track=48 --weather=snow
build/macos-arm64-m9/Debug/RRR3d --verify-resources --track=64 --weather=hell
```

- track 0: World1 grass/default material path;
- track 16: World2 water, rain and reflection;
- track 48: World5 snow and `glPlanarRefl`;
- track 64: World4 magma and hell lighting/fog.

The final validation additionally builds the arm64 Debug target, runs the
original physics/session smoke, and runs representative Cocoa/Metal race
smokes after all code changes are complete.

The final run completed successfully:

- the executable is an arm64 Mach-O with minimum macOS 13.0;
- physics/session provenance resolved 1175 original collision triangles and
  passed vehicle, countdown, checkpoint/lap/finish, weapon/damage, bonus
  and respawn checks;
- World1/fair completed 240 frames at maximum smoke speed 9.22333;
- World2/rainy completed 240 frames at 6.35343 and reported actual
  Reflection and Water submissions;
- World5/snow completed 240 frames at 8.89762 and reported the conditional
  Reflection submission;
- World4/hell completed 240 frames at 9.54877 through the magma path;
- every runtime case kept four wheel contacts and verified six rendered
  cars, both original camera modes, frame-target resize, Shadow, Scene,
  64→16→4→1 luminance, Adapt, Bloom, Composite and HUD passes.

## Remaining backend differences

This milestone does not claim bit-identical D3D9 pixels. The old
`glRefl` cube-map and secondary normal-map contracts are represented by
portable material branches until their full multi-sampler material records
are carried through the asset API. Trail particles do not yet build the
legacy connected dynamic strip. Jolt/PhysX and SDL/X3DAudio numerical/DSP
differences remain unchanged.
